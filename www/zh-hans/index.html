深入智能体运行框架之下

比护栏更深一层的保护。

我们分析了超过 10,000 个软件包对凭据的使用，并为支持的工具开发了加固器。

Automic Vault 在软件包层面加固支持的 Tool：通过重新配置、包装或打补丁来保护凭据的使用方式。无论请求来自 Terminal、Claude Code 还是其他应用，受保护的凭据请求都要经过 Authorization Gate。

AWS

每次调用使用短期凭据。

普通 AWS 命令使用短期会话凭据。长期密钥从共享凭据文件中移除。AV 为每个 AWS 进程单独获取会话凭据。

决定工具和智能体能做什么

让智能体全权限运行，凭据使用由你掌控。

保留智能体的全权限执行模式，同时由 AV 单独控制它对受保护凭据的使用。AV 不会将智能体放入沙箱，也不会阻止任意本地文件修改。

允许代理读取 GitHub issue，同时要求写入操作经过你的 Approval。终端可以使用不同规则。AV 按 Verified Launcher 检查完整操作。Write Access 仍要求密钥披露和使用更强大凭据的操作获得 Approval。Unknown 操作始终需要人工判断。符合条件的代理任务可在一个 Gate 获得十分钟有效时间的 Write Access，你可以延长、暂停或结束授权。

给智能体所需的能力

把审核过的能力交给智能体。

实际效果

决策所需的信息，一目了然。

允许操作之前，先查看软件、命令、参数、工作目录和 Secret Names。

让项目密钥远离明文文件

多个项目可以使用相同 Secret Name，但各自保存不同的 Project Value。AV 选择最近匹配的物理目录对应的值；没有匹配项时使用 Global Value。对于兼容的 HTTP 客户端，Secret Proxy 向应用提供临时引用，并仅向获批目的地应用真实凭据。

了解 Project Values → 了解凭据代理 →

目录选择 Values，不授予权限。同一 Secret Name 下的所有 Values 受相同策略约束。代理引用属于持有者凭据，可以使用会话已获准的访问权限。

审批多台 Mac 上的操作

在同一 iCloud 钥匙串账户下符合条件的 iPhone 上查看已登记 Mac 的请求。每台 Mac 保留自己的 Secrets、策略和 Authorization History，并在本机执行决定。你也可以在某台 Mac 上启用 Touch ID Approval，通过生物识别允许操作。

设置 iPhone 和 Touch ID Approval → 通过 TestFlight 加入 iPhone 公测 →

iPhone Approval 会移除 Mac 上通过鼠标和键盘允许操作的入口。请关闭 iPhone Mirroring 和 Show on Mac，或要求每台符合条件的 iPhone 使用 Face ID 或 Touch ID。中继不可用不会启用替代方式。

了解保护边界

AV 保护支持的凭据和敏感 Tool 操作，应对以普通用户权限运行的代码。root 或内核失陷、任意本地破坏，以及 Target 收到 Secret 后的行为，不在保护范围内。

查看凭据的使用情况

Authorization History 在本地保存允许和拒绝的请求。AV 在释放 Secret 前保存并验证获准 Secret Use 的记录。历史记录有容量限制，不保证防篡改，也不是完整的取证日志。
