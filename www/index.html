The tool should have to ask.

Automic Vault keeps the credential out of the agent’s context. The tool request stops at a native approval gate where you can inspect the command and allow it once—or deny it.

A readable credential lets another local process act as you.

Cloud CLIs, source-control clients, deployment scripts, and release tools can read private data or change remote systems. Their credentials often sit in files that every local process can read.

The secret belongs to the tool invocation.

Store long-lived values in the Automic Vault Keychain. Name the executable that may receive them. Automic Vault loads each value after approval and places it in that child process.

Values stay out of prompts and project files.Agents can request work without reading the raw credential.

Native helpers narrow the handoff.AWS credential_process, Kubernetes ExecCredential, registry helpers, and other tool protocols avoid ambient shell exports.

Security at the executable layer.

Automic Vault uses the facts your Mac has at execution time: the binary on disk, its path, arguments, parent process, working directory, and tool-specific credential protocol.

Central vaults can remain your source of truth. Automic Vault controls the last local hop where a developer tool receives a credential and acts with it.

Three commands establish the boundary.

A local boundary you can inspect.

Automic Vault is Apache-2.0 open-source software. Its security model assumes macOS Keychain, System Integrity Protection, and the signed app remain trustworthy. Root compromise and a malicious approved executable remain outside that boundary.
